SCOPE (R2)
----------
Narrow defect correction for Process.BendAngle OPC reads staying at 0 while forming was active.
Formal closure of SIM-P01 Machine-2 simulator basis. No VIGIL changes. No new machine features.

ROOT CAUSE
----------
PressBrakeKinematicsEngine allowed physically inconsistent state where Process.FormingForce remained
positive while BendAngleDeg was 0 (forming force used a 0.2 progress floor; approach/return decay
zeroed angle before force). Phase-transition ticks could also enter Forming without applying forming
kinematics on the same tick, leaving BendAngle at 0 until the next engine tick.

CORRECTION
----------
- Align FormingForceKn with forming progress (removed 0.2 base offset).
- SyncForceToBendAngle: force goes to 0 when angle reaches 0 outside active forming/hold.
- Phase overflow chaining on RamApproach->Forming, Forming->Hold, Hold->RamReturn so bend state
  updates within the same tick when simulation dt spans phase boundaries.
- Live harness: peak-range OPC sampling for BendAngle/FormingForce/Ram; BendAngle dynamics require
  non-zero OPC peak (GT fallback removed).
- Regression test SIM_P01_R2_BendAngle_TracksFormingPhase_InRuntimeAndOpcPath.
